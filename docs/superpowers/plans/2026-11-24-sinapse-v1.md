# Sinapse v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port the Python RAG prototype to a generic, self-contained C# .NET CLI (`sinapse`) that indexes configurable markdown folders into SQLite FTS5 and serves BM25 search to Claude Code over MCP.

**Architecture:** `Sinapse.Core` (class library: config, chunking, indexing, search, savings log, report) has no knowledge of console or MCP. `Sinapse` (console exe) routes commands `index | mcp | report | --version` to Core. Concrete classes; DI only where the MCP SDK host requires it.

**Tech Stack:** .NET `net10.0`, `Microsoft.Data.Sqlite` (bundle e_sqlite3, FTS5), `ModelContextProtocol` (official SDK, stable 2.x, stdio), `Microsoft.Extensions.FileSystemGlobbing`, xUnit, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-24-sinapse-design.md` — read it before starting; this plan argues from it.

**Prototype (reference only, never modify):** `<vault>/<pasta>/.rag/` (local, fora deste repositório) — `build.py`, `query.py`, `kb_mcp.py`, `gen_savings.py`. Never read or copy `rag.db`, `savings.jsonl` or any vault note: they are private.

## Global Constraints

- Target framework `net10.0` (SDK 11 is installed; that's fine).
- Repo root: the repository root, remote `origin` = `https://github.com/VoidPep/Sinapse-RAG.git`. Branches: `main` (releases), `develop` (integration), and the work branch `feat/sinapse-v1` (already checked out; all commits of this plan go there). Do not push — the main agent pushes and opens the PR to `develop`.
- `LICENSE` already exists on `main` (MIT, `Copyright (c) 2026 Pedro H. Martins`) — keep it, don't recreate.
- No reference anywhere (code, tool descriptions, README, fixtures) to the company, the author's username, or local paths. Names: product `Sinapse`, exe `sinapse`, MCP server name `sinapse_knowledge_base`.
- MCP tool names and parameters unchanged from the prototype: `buscar_conhecimento(pergunta, k=6 max 20, tipo?, pasta?)`, `registrar_fallback(pergunta, manual_tokens)`, `reindexar()`.
- In `sinapse mcp`, stdout is the protocol channel: all logging goes to stderr.
- Chunking constants: `Max = 1200` chars, minimum chunk `30` chars.
- FTS: `tokenize='unicode61 remove_diacritics 2'`, ranking `bm25(fts,5,3,1)`, score = `-bm25` rounded to 2 decimals.
- Search connections: `Mode=ReadOnly;Pooling=False`.
- Exit codes: `0` success, `1` runtime error (incl. usage error), `2` config invalid/missing.
- Publish: `--self-contained -p:PublishSingleFile=true -p:InvariantGlobalization=true`, RIDs `win-x64` and `linux-x64`.
- Fixtures are synthetic content only.

## Review Focus

1. **UTF-8 BOM or CRLF notes** (common on Windows teammates' vaults) — frontmatter must still be recognized and chunks must not carry `\r`. → tests in Task 4.
2. **`index` while another process has `index.db` open** (a Claude session running `sinapse mcp`) — swap succeeds or old index stays intact, exit `1`, no half-written db. → test in Task 5.
3. **Search before any index exists / `dataDir` missing** — friendly message, no crash, and must not create an empty `index.db` as a side effect. → tests in Task 5 and Task 8.
4. **Questions with FTS syntax or punctuation** (`"`, `*`, `-`, `AND`, `NEAR(`, only short words) — never throws; short-only question returns empty. → test in Task 5.
5. **Paths with spaces and accents, folders outside `base`, non-existent folder in `folders`** — indexed with correct relative/absolute path; non-existent folder is a config error (exit `2`). → tests in Task 2.
